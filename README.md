# Codex 桌面端 XLSX 附件一直转圈的临时解决方法

**在当前聊天右侧打开一个已有的 Pages 页面编辑器，保持它显示，再发送 XLSX 附件。** 这一方法已在下述 Windows 环境中验证成功。关闭页面后故障复现，重新打开后恢复发送。

## 适用现象

- 添加 `.xlsx` 文件并点击发送后持续转圈，任务文字仍留在输入框。
- 同一环境下，纯文字消息和 Word 附件可以正常发送。
- 重装同一版本后仍然复现。

## 操作步骤

1. 先复制保存尚未发送的任务文字。如果输入框已带有卡住的 XLSX 附件，先移除附件卡片。
2. 在发生故障的聊天中，让 Codex 把一个已有的 Pages 页面打开到当前聊天右侧。
3. 确认右侧已经显示该页面的编辑器，保持面板打开。
4. 按原来的方式添加 XLSX 文件，恢复任务文字并发送消息。
5. 确认消息已提交，并让助手读取表格，检查附件是否真正可用。
6. 后续发送 XLSX 时继续保持该页面编辑器打开。如果关闭后再次卡住，重新打开同一页面再试。

可以把下面这句话发给 Codex，将页面名称替换成自己的已有页面名称。

> 请把我的“页面入门指南”在当前聊天右侧打开，并保持页面编辑器显示。

测试使用的是 **Pages 的页面编辑器**。普通网页、本地文件预览以及其他右侧面板的效果仍待验证。操作需要当前账号能够打开已有 Pages 页面。

## 实测结果

测试日期为 2026-11-05，北京时间。三次测试在同一聊天中使用同一份 XLSX 文件。

| 次序 | 当前聊天右侧状态 | 结果 |
| --- | --- | --- |
| A | 已打开 Pages 页面编辑器 | XLSX 成功发送，附件引用到达聊天，表格只读解析成功 |
| B | 关闭该页面编辑器 | 再次无法发送 |
| A | 重新打开同一页面编辑器 | 同一 XLSX 再次发送成功，附件引用到达聊天 |

| 项目 | 值 |
| --- | --- |
| 系统 | Windows |
| 桌面应用包 | `OpenAI.Codex` |

| 内部应用版本 | `26.1029.61003` |

## 可能的原因

诊断记录显示，卡住的提交反复请求 Pages 创建能力接口，并得到 HTTP 200，文件上传尚未开始。当时允许文件导入的类型列表为空。

客户端静态检查发现，XLSX 会进入专门的导入准备流程。客户端也已有普通本地附件回退逻辑，因此空导入列表本身不足以解释持续转圈。

可疑点是能力查询的 `gcTime: 0` 与附件准备完成后的提交重放共同作用。如果能力结果在重放前被回收，提交可能再次进入准备。Pages 页面编辑器持续订阅同一能力查询，可能使结果保留到下一次提交，从而允许普通本地附件回退继续执行。

上述机制与“打开成功、关闭失败、重新打开成功”的测试结果吻合。具体循环分支仍缺少运行时追踪，当前将它作为有静态检查和复测支持的解释。

## 已知范围

- 目前验证的是上述版本、当前账号和同一聊天中的 XLSX 发送。
- 应用重启后、其他窗口、其他账号及其他版本的效果仍待验证。
- XLS、CSV、PPTX 等格式尚未按这一方法实测。
- 该方法依赖右侧 Pages 页面编辑器保持打开。持久修复仍需客户端改进附件准备、能力缓存和提交重放流程。
